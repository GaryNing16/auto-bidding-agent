# 赛题规则与本地环境约定

依据：团队当前《广告智能出价 Agent 赛题整理》《项目指南》，以及 2026-10-20 对 `request_id` 的确认。正式 SDK 和评测器发布后，以其签名和结算细节为准，更新本页及对应测试。

## 已确认的任务

| 项目 | 实现必须保持的含义 |
| --- | --- |
| 投放周期 | 一天 72 片，每片 20 分钟；空片仍需推进 |
| 动作 | 片开始返回一个非负系数 α，同片固定；逐请求报价为 α × 该广告主的 pvalue |
| 参与关系 | 同一 `request_id` 是一次拍卖；只有有记录的广告主参与。缺失配对不补零 |
| 请求顺序 | 请求逐个结算，前一个请求消耗后的余额影响后一个请求 |
| 价值 | 同一请求对不同广告主的 pvalue 可不同；竞胜者获得自己的 pvalue |
| 拍卖 | 单广告位二价，零报价不参与；单一有效参与者付款为零 |
| 目标 | 最大化全天竞胜 pvalue 总和，同时总消耗不超过预算 |
| 在线信息 | 只用已允许的配置及自身历史；未知当前片机会数和价值，未知对手轨迹 |
| 离线训练 | 完整历史请求可供环境回放及构造标签，不自动成为在线观测 |
| 重置 | 每局重新初始化预算和策略状态，不保留上一局隐藏反馈 |
| 对手 | 在当前局重新出价、消费并更新；不照搬历史日志报价 |

`pvalue=0` 的合法记录和完全没有该广告主记录是两个不同事实，统计时要分开。前者按报价公式得到零报价，也不会有效参拍。`NaN`、无穷、负数、重复 `(request_id, player_id)`、同请求跨时间片、角色类型变化等属于输入错误，不能静默修复。

## 为了先运行而选择的本地约定

| 配置 / 边界 | 当前实现 | 后续核对点 |
| --- | --- | --- |
| `alpha_max` | 默认 5.0，显式可配；超界和非有限动作报错 | 主办方实际上限及非法动作处理 |
| `budget_policy=cap_bid` | 每次请求将有效报价限制在当前余额内，再做二价结算 | 官方是否裁剪报价、剔除参拍或采取其他规则 |
| `budget_policy=reject_unaffordable` | 先排序；若赢家无力支付，剔除该赢家并重新结算 | 这是对照假设，不代表官方语义 |
| 零预算 | 不再参与，包括潜在零付款机会 | 需核对官方边界行为 |
| `tie_break=seeded_random` | 按种子和请求身份生成可复现优先级 | 官方固定随机规则的精确形式 |
| `tie_break=stable` | 按角色 ID 固定优先级，用于手工核验 | 不是默认公平性结论 |
| 金额 | 浮点数结算与小数误差容忍 | 官方金额精度、舍入时机及最小单位 |
| 缺省片号 | 内部 0–71；每份请求文件表示一局 | 正式数据是否从 1 开始、跨文件 ID 是否复用 |
| 预算及类别 | 独立 JSON 配置；角色可无请求但仍应在配置中 | 官方每日预算和配置格式 |
| 提交函数 | 本地 `Agent` 的 bidding/update 契约 | 正式 SDK 参数、返回格式、超时处理 |

这些选择集中在配置和环境，不应散落进学习策略。用一个差异例子检查预算规则：A 报 10、余额 5，B 报 8、余额充足。裁剪报价时 B 胜并付 5；剔除无力付款赢家时 A 被剔除，B 成为单一参与者并付 0。两者均不超预算，但训练出的行为可能不同。

## 观测边界与目标

策略输入包含当前时间片、自身初始预算/余额/类别、系数上限和自身过去的系数、竞胜数、费用、价值。历史竞胜数不等于历史机会总数。不会向策略传入当前请求表、当前参与者、对手余额或未发生的 pvalue。

PPO 的单步对应完整时间片，原始奖励使用该片竞胜价值。自然完成一天是 `terminated=True, truncated=False`。有限期价值和目标先用 γ=1；不把“尽快花完预算”“利润”或 ROI 替换为题面目标。自身历史摘要不保证马尔可夫性，此问题仍可能需要更好的历史建模。

环境与策略的 Python 接口提供信息隔离约定和测试，但不构成执行任意恶意 Python 的安全沙箱。正式提交仅交付策略及模型，不能把完整回放请求随 Agent 读入。

## 比较与成绩

固定系数用于校验；`PacingPolicy` 是本地自建预算控制基线，不是主办方未公开的 PID。所有本地相对比值都应标注 `local_pacing`，不得作为正式成绩。

应按完整日期/投放期划分数据；同一请求流、预算、角色和种子比较候选策略。正确的多局归一化指标是逐局相对基准比值的平均，不是把全部价值相加后再求比。基准为零的局必须单独报告，正式零分母规则仍待确认。单策略替换和多策略同场需要分别记录。

资源约束是 bidding 与 update 的 P99 合计不超过 200 ms、峰值内存不超过 4 GB；本地 smoke 证明调用链可运行，不能代替正式环境下的性能验收。
