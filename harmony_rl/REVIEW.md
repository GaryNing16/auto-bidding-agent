# PPO + LSTM 实现独立复核

审计日期：2026-10-28。审计对象为用户附件中的完整需求、新增 `harmony_rl` 代码、相关测试、冻结 Baseline 的复用协议，以及本轮已经提交的训练记录。本文件是实现可靠性审计断面，不是尚未完成的 Test 成绩报告。审计没有读取或汇总未完成 Test 的成绩，也没有据 Test 调参。

## 审计判断

当前预先声明的实验路径未发现会使训练结果失效的第二套拍卖规则、未来数据输入、PPO 新旧概率坐标混用或旧轨迹混入 Actor 的问题。环境、标准 PPO、LSTM 重分配、Residual PPO、冻结评测和诊断均有实际代码及针对性测试；不能据此宣称 PPO 已超过十种 Baseline。

审计时真实市场 E1–E5 已各提交 96 条训练轨迹并完成验证，E6 尚在执行；`pilot/evaluation/status.json` 尚不存在。因而当时不能给出完整 Test 排名、稳定收益或最终比赛推荐。最终状态应读取本轮正式评测 `status.json`、覆盖表及报告，不沿用本快照中的进度。

## 本轮发现并已修复的问题

1. **独立评测入口原先未核验模型资格。**只读探针证实：原 `checkpoint_candidates` 接受 `smoke_e4_v2/best.pt`，尽管其 `config.smoke=True`、仅有4个合成训练episode，仍返回正式 `PPO-LSTM-Aug` 标签。按父任务授权，在正式Test开始前修复 `evaluate.py`：现在拒绝smoke与未选中的 `last.pt`，要求同目录selection/status证据、checkpoint SHA一致、selection的update/episode/value与模型内验证记录一致，以及算法/训练seed一致。显式PPOAgent manifest同样在读取任何测试市场前复核，资格证据写入评测协议。真实E1/E2 best通过实际资格检查，原smoke被明确拒绝。

2. **合法早停与完整交互预算需要区分。**资格检查允许有完整验证和选模证据的 `early_stopping` 模型，但记录 `complete_interaction_budget=False`。选中模型可以来自第48个episode，最终训练完成96个episode；代码要求selection与模型对应，不错误要求选中进度等于最终进度。时间到期或普通未完成训练不能借此进入正式评测。

3. **PPO训练日志合并与串行随机流。**集成期发现重复metrics关键字会导致训练写日志时异常，以及串行rollout会改变trainer全局Torch RNG。已经分别修正为无重复合并及采样阶段RNG隔离；训练、续训与部署测试已实际验证。

4. **半次optimizer更新不能作为恢复边界。**原中断处理存在把部分更新权重配旧episode_count写回的风险，已修为仅保留最后完整提交的last.pt。针对性测试在真实PPO optimizer更新后再将参数加123并抛出KeyboardInterrupt，确认持久checkpoint仍为前一边界，随后恢复所得Actor/Critic/LSTM均与不中断运行逐tensor相同。

5. **消融不能只凭两个算法Test都完整就声明等预算。**已通知报告实现补充训练来源、模型SHA、交互数和训练seed检查；审计复读的 `report._training_records` 与 `_ablation_status` 已加入这些检查。不符条件时不能输出“同预算方法效果”的解释。

上述修复没有改变训练时的拍卖语义。评测资格修改发生在本轮正式Test冻结之前；训练执行指纹不包含评测脚本，因此不修改已完成训练模型的来源。

## 尚存边界和后续维护点

- **训练完成不等于收敛。**本轮每变体96轨迹、12次PPO批更新，只有一个训练seed。两个评测seed主要改变平局及混合分配，不是独立训练重复。无法据此证明稳定LSTM收益、数据增强鲁棒性或收敛上限。
- **Test完整性仍需等待实际结束。**计划为每变体48角色×5场景×2评测seed=480局，六变体2,880新局；既有Baselines7,680局复用。AUDIT中的“双训练seed5,760局”是先前工作量估算，不是本轮实际请求量；本轮真实协议明确单训练seed。
- **比较日期不是新盲测。**period-24已在历史报告展示；不能把同一日期的新模型比较称为独立未见市场验证。period-25等独立日期及更多训练seed未完成时必须明确写未完成。
- **机会成本尚属诊断。**Raw Critic有限差分仍可能噪声很大；LSTM Critic估计的是剩余重分配return，不是原始剩余价值。实现已分别标记，未把它们加到训练reward。单个预算反事实不能证明因果贡献，也不能证明“机会成本建模提高了PPO”。
- **预测误差和策略改进需分开。**训练buffer前缀MSE是监督训练指标；评估前缀泛化需冻结predictor在Validation上另测。即使return守恒、预测误差下降，也不能推出早期预算决策改善。
- **中断时的多文件窗口仍需谨慎。**last.pt是恢复权威；训练JSON、轨迹NPZ、LSTM版本文件可能在最后完整提交之前已经写入。图表应按已提交checkpoint计数过滤。另在验证改善后，last.pt、best.pt、selection.json并非一个原子事务：中断恰落在写入间隙时可能产生不一致；新的正式准入会拒绝这种不一致，不能静默发布。正常完成的本轮运行不受此窗口影响。
- **恢复后的报告配置核验应尊重允许变化。**训练允许恢复时修改episodes/workers/max_seconds；若旧best仍最佳，best内保留旧值是合法的。报告不得因此把已验证的旧best误判为不同算法。已通知主任务按训练不可变字段核验。
- **时限不是任意时刻强制切断训练。**训练在完整采样批次间、验证开始前检查；正在执行的整批可以越界，初始化载入另有开销。评测则保留已原子提交的局并重新运行取消局。不能把给定阈值当作严格进程墙钟上界。

可以说明系统已经完成实现并通过有针对性的功能、规则一致性及恢复验证；已有完整训练记录可审计，冻结评测已具备严格来源和覆盖检查。只有正式Test全部完成、报告完整性和模型资格通过后，才能回答当前有限训练预算下哪个PPO变体更好、是否超过最佳Baseline。关于稳定增益、独立市场泛化、真实机会成本解释和比赛最优策略的结论，仍必须限定在实际证据范围内。
